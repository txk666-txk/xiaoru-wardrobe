# 穿搭对话与数字人修复记录（2026-11-20）

## 后续：模型提示与指定白裤（同日）

本次完整回归结果：407 项 Python 测试、26 项前端测试通过。小如主应用已重启，首页和试衣状态接口均返回 HTTP 200，标准启动器成功复用独立共享的 GPU 试衣服务。

用户报告“保留上衣，帮我再换一个白色裤子”出现“模型服务暂不可用”。旧代码把接口失败和模型 JSON/参数校验失败统一显示成服务不可用，而旧日志没有记录安全原因码，因此无法确定截图对应那一次的具体异常。不能凭这张提示断言接口断线、额度不足或请求超时。

本轮已区分响应超时、接口繁忙、认证/配置、连接异常、决策校验失败及未知失败，并记录安全原因码、规则接管动作与调用耗时；不记录原始异常、密钥、照片、完整用户文字或身份。预算等非法参数和接口响应结构错误也统一归入明确的校验码。提示词强调只输出本轮变更，不照抄历史预算，并补充保留上衣/更换白裤的格式示例；没有放松证据和权限校验。

使用独立临时会话、真实配置模型和本机 1009 件商品目录复现该原话：修复前模型决策成功，但工具第二套把白色半身裙当成下装推荐。现已增加按部位的指定颜色和裤装/半身裙类型筛选：明确要求白裤就必须是有白色资料的裤装，保留原上衣；无合规商品时说明未找到，不擅自替成裙子或其他颜色。新条件保存在会话中，后续修改预算不会丢失，明确换色会替换该部位旧的指定色。

修改后同一原话真实模型决策约 3.21 秒完成，未回退，工具两套均保留原上衣并返回白色裤装。这个单次耗时不是稳定延迟指标，也不能证明外部接口今后不会失败。颜色依据商品标题或 SKU 资料，未证明商品默认图片和每个实物规格一致。明确切换连衣裙会清理旧裤装约束，但仅推荐连衣裙的完整协议仍未验收；本轮没有重新执行 GPU 试衣生成。

## 原因与行为

原文本模型接口快速返回 HTTP 429，穿搭图随即回退规则；前端没有展示回退信息。规则也没有解析“价格不限”和按服装部位排除颜色，导致沿用旧预算。

现在本机配置复用原 Fay 已配置且可用的远桥云文本接口。模型决策后由程序执行商品工具和硬约束检查；接口失败时在本轮商品建议旁显示回退提示。没有人为延迟，也没有展示内部思维来冒充规划。

- “价格不限”清除历史金额；之后给出新金额可重新设置预算。
- 上衣、裤装、外套分别保存禁色，后续补充一项不会丢失其他条件。
- 明确提到的品类需要出现，不能通过跳过外套或改成连衣裙绕过要求。
- 颜色未知的商品不会声称符合禁色要求；照片里的冲突单品也要替换，其他已有单品仍可保留。
- 回复列出本轮条件和第一套具体商品，商品卡可继续试衣。商品可能有多个颜色规格，颜色初筛依据目录资料，实际仍需核对商品图及所选规格。

数字人静态问题来自默认模型名与本机资源名不一致；未指定模型、默认资源不存在、且仅安装一个合法模型时自动选择该模型。显式设置仍优先，缺少资源的 GitHub 版本仍有备用头像。

## 验证

使用既有本地环境执行完整回归：386 项 Python 测试、26 项前端测试通过。真实远桥云穿搭决策与商品工具样例通过，metadata 为 model 且未回退；网页实际对话也显示“模型决策”、567/587 元两套结果及不限预算。测试案例不能代表所有自然语言都能正确理解。

网页日志确认 Live2D 模型已加载，口型参数为 ParamMouthOpenY；动态形象和实际回复商品卡已在浏览器查看。共享试衣模型通过标准启动器恢复连接；这轮没有重新执行一次GPU试衣生成。

本机配置 system.conf 不提交仓库。共享模型曾由另一个入口使用不同认证运行，本轮通过重新启动标准共享服务恢复一致，未提取运行进程凭据。政策 RAG 在线证据选择另一次检查发生超时并回退原文，本次穿搭成功不代表政策生成全部验收通过。
