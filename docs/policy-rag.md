# 政策知识检索

客服处理政策咨询时，会从本地 `agent/data/policies.json` 检索相关条款。当前仅这份 JSON 进入索引，`agent/data/knowledge/` 下的 Markdown 文件尚未自动导入；订单、物流、商品数据也没有进入这个政策索引。政策区分法律依据和演示店铺规则，演示规则不代表真实商家承诺，实际适用条件以现行法规和店铺公示为准。

## 工作流程

```text
客户问题 → 客服路由 → 政策工具 → 本地语义检索与关键词加权
        → 找到政策及来源 → 受限证据选择 / 原文回退 → 客服回复
```

索引将政策按句切分，用本地 `BAAI/bge-small-zh-v1.5` 生成向量，在 CPU 上计算相似度，并用少量关键词分数辅助排序。命中句子后映射回完整政策，回答时保留其条件和例外；检索结果包含政策 ID、来源及分数。低于阈值时提示补充信息，无法保证语义匹配永不出错。

回答环节可调用已有的兼容 OpenAI 格式的文本模型，只允许其从检索到的政策证据中选择 ID；后端校验 ID，再用可信原文构造回复，模型不直接编写退款条件。调用超时、服务异常或输出无效时回退原文。当前精简政策回答通常只有一条候选，因此不是多文档自由总结或复杂规划。政策检索不执行退款：订单归属、二次确认和演示交易限制仍由原有业务代码控制。

## 准备模型

先安装主项目依赖，然后在项目根目录执行（将 Python 路径替换为自己的环境）：

```powershell
& "YOUR_EXISTING_ENV\python.exe" scripts/setup_policy_rag.py
```

脚本从 Hugging Face 下载 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 到用户缓存，并验证 CPU 能生成向量。使用前请核对模型页面的许可和适用范围。权重不放进 Git，加载失败时回退原关键词检索；模型准备完成后重新启动工作台。用户请求过程不会触发模型下载。

可选环境变量：

- `FAY_POLICY_RAG=off`：关闭本地语义检索，使用原有关键词查询。
- `FAY_RAG_MODEL_PATH`：指定兼容的本地向量模型路径；未设置时使用默认模型缓存。
- `FAY_RAG_GENERATION=off`：不调用文本模型选择证据，直接输出政策工具返回的原文。

## 如何验证

```powershell
& "YOUR_EXISTING_ENV\python.exe" -m unittest test.test_policy_rag
& "YOUR_EXISTING_ENV\python.exe" scripts/evaluate_policy_rag.py --split test --output cache_data/policy_rag_eval.json
```

单元测试使用模拟编码器和模拟模型，验证检索结果处理及回退，不证明在线模型可用。评测脚本要求真正加载本地向量模型，比较固定小样本上的关键词与混合检索；它只测政策工具的检索，不能代表完整对话质量、线上准确率或生产效果。报告写入被 Git 忽略的 `cache_data/`。

本次接入验证时，本地向量模型已在 CPU 成功运行；已配置的在线文本模型返回 HTTP 429，所以真实在线证据选择尚未验证成功。调用失败时的原文回退已验证，之后需要恢复模型额度或服务，再实际测试在线选择和对话体验。

输入发送给文本模型之前会对常见号码、邮箱、密钥和身体数据做有限脱敏，并不保证覆盖所有个人信息；不要将客户照片或订单隐私当作政策知识提交仓库。

## 本次验证记录（2026-11-19）

- 本地 CPU 模型和真实政策检索可用。27 条人工编写的测试问题中，混合检索第一条结果或拒答符合预期 23 条，原关键词方式 9 条；其中相关政策分别为 19/22、4/22，无关问题拒答分别为 4/5、5/5。这只是政策工具的小样本对照，不是盲测或线上准确率。仍存在发货、隐私问题误匹配和一条无关问题误命中。
- 本机冷加载和建索引约 13.6 秒；同一次测试预热后检索中位数约 10.2 毫秒，仅供本机参考，不包含完整对话和模型生成。
- 对一般聊天增加保守路由门槛；这不是完整提示词注入防护。经 Fay 文本适配层实际检查退货、质量售后、普通聊天和订单权限等案例；真实语音及数字人播放未进行人工端到端验收。
- 在关闭在线证据选择的情况下，完整项目回归通过：360 项 Python 测试和 26 项前端测试。测试包含模拟组件，不代表线上接口可用。
