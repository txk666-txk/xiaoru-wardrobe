# 上下文模型工具路由

文字和语音最终通过 `agent.fay_adapter.handle_text()` 进入 Controller。普通请求默认交给已配置文本模型，由它结合近期对话、穿搭条件和上一套商品选择业务路由和受限参数。后端将路由映射到已有工具或穿搭图。通用聊天可在同次模型调用中直接回复。

## 实际分工

Controller 整理上下文，`intent_router.py` 校验模型输出的 `intent`、`confidence`、`operation`、`updates`、`evidence` 和 `reply`。模型选择业务类型与参数，Controller 调用对应处理器。业务实体ID仍从本轮原文提取，用户归属由服务器提供。

业务路由包括商品、尺码、穿搭、订单、物流、政策、售后咨询和售后执行申请。穿搭内部仍运行 LangGraph。商品查询可传递经校验的单品类别、目标款式和预算，因而“外搭”可以转成外套筛选。模型输出 JSON 动作，应用校验后执行已有 Python 工具。

## 多轮纠正

会话内保存最近8条脱敏消息，每条最多350字，超过30分钟不再读取。模型还会收到当前场景、预算、颜色、目标款式、待补字段和上一套商品摘要。当前图片字节、路径、会话ID和身体测量数值不会进入这些上下文。会话内的请求串行处理，避免并发覆盖历史。

用户说“我是男的，你这搭配怎么又有男装又有女装”时，模型应选择穿搭路由，传入 `gender=男款`，同时提供本轮原文证据。后端合并原场景、预算和颜色，并重新执行推荐。“我是男的，给女朋友买件外套”进入商品查询，目标为女款。

商品筛选优先读取明确的商品、SKU和类别性别字段，再使用标题。明确要求男款时，只接受可核验的男款或中性商品。筛选后没有满足颜色和预算的组合，会提示暂无匹配。商品字段冲突或不明时不会作为明确性别候选。

## 普通聊天和故障回退

模型选择 `general` 时，可以结合对话直接填写 `reply`。后端审核后返回，并加入同一会话历史。兼容旧分类器时若只返回general而没有回复，继续交给原 Fay 通用对话。

分类置信度必须是0到1的有限数字，采用0.75作为启用模型路线的阈值。该分数来自模型，真实效果需要用独立样本持续评估。业务分类低分、调用异常或输出无效时，使用原规则、保守的政策检索兜底或原通用回复。

已授权附件由原穿搭图处理。售后执行申请始终进入原订单核验和明确二次确认。确认令牌、用户归属和高风险操作检查由后端执行，模型输出不能直接确认交易。

## 配置与验证

实际入口默认启用上下文路由，复用当前文本接口、模型名和密钥。请求最多生成500个token，连接超时5秒、读取超时15秒。读取超时约束连续无数据的时间，不能作为整轮响应时限。进入穿搭图后可能继续发生模型调用。

启动前设置 `FAY_INTENT_ROUTER=off` 可使用规则模式，设为 `model` 恢复上下文模型路由。修改后重启应用。

```powershell
& "YOUR_EXISTING_ENV\python.exe" -X utf8 -m unittest test.test_intent_routing test.test_styling_gender
```
